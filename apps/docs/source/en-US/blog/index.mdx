## How we compare products

These articles separate verified product capabilities from design tradeoffs. They use official documentation as the primary source, acknowledge features where a competitor is stronger, and include Clarify's current gaps instead of presenting a parity checklist.

## What we write about

- **Content ownership**: Markdown, MDX, and OpenAPI specifications stay in the project repository, where they can be reviewed, reverted, and migrated.
- **Publishing reliability**: preview, validation, static builds, and search indexing belong to one publishing pipeline.
- **Different readers**: the same content should read well on the page and remain accurately discoverable by search and AI.
- **Progressive expression**: keep ordinary explanations in Markdown and introduce MDX components only when interaction or structure earns its place.
